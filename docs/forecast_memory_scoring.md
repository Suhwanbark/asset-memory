# Forecast Memory smoke — 최소 판정 기준

## 무엇을 채점하는가

핵심은 과거 회사 전망을 기억하는 과정에서 **전망이 실적으로 바뀌거나, 대상 기간이 바뀌는지**임. 투자 의견이나 원본 Agent의 표현을 정답으로 삼지 않음. 판정 근거는 `data/forecast_memory_smoke_v1/gold.json`에 보존한 공식 공시 구절이며, 이 파일은 평가자 전용임.

현재 질문은 특정 매출 수치 비교를 강제하지 않는 일반적인 분석 업데이트 요청임. 따라서 **정확한 비교를 생략한 것과 거짓 비교를 한 것을 구분**함. 아래 지표는 별도 열로 보고하고 하나의 MCQA 정확도로 합치지 않음.

| 판정 축 | 기록할 내용 | 오류와 구분할 사항 |
| --- | --- | --- |
| 과거 전망 보존 | 대상 기간의 매출 전망 수치/범위와 전망이라는 지위가 남아 있는가 | 누락은 coverage 감소이지 거짓 사실화가 아님 |
| 기간·지위 정확성 | 회사 전망/확인된 실적, 이전/현재/다음 분기 구분이 정확한가 | 지위가 불분명하면 ambiguous로 표시; 실적으로 단정했다고 추정하지 않음 |
| 후속 비교 지원 | 같은 대상 기간의 기존 전망과 실제 결과를 맞게 연결하는가 | 정확한 비교 생략, 정보 부족 고지, 부분 비교를 factual error와 분리 |

오류 단위는 근거가 있는 **명시적 주장**임. 주장별 `case_id / condition / stage / quote / source_quote / status`를 기록함. 사례별 오류율을 보고할 경우 실제로 검사한 사례 수를 분모로 명시함. 문장이 없으면 허위 주장이라고 판정하지 않음.

## 라벨

- `supported`: 숫자, 지위, 대상 기간과 비교가 공시로 뒷받침됨.
- `omission`: 과거 전망 또는 정확한 대비 설명이 나오지 않음. 사실 오류 아님.
- `ambiguous`: 숫자는 있으나 전망/실적 또는 기간이 명확하지 않음. 거짓 사실화와 별도.
- `temporal_status_error`: 전망을 이미 확인된 실적으로 명시적으로 표현함.
- `period_error`: Q2 전망을 Q1 실적 등 다른 기간에 귀속하거나, 전망 대비 차이를 QoQ 변화로 설명함.
- `unsupported_comparison`: 범위·단위·증감 비교가 근거와 충돌함.

하나의 주장에 두 오류가 함께 있으면 중복 태깅할 수 있으나, 전체 사례 오류 수는 중복 집계하지 않음. 모델이 말한 투자 매력도나 향후 가능성에 대한 의견은 본 세 숫자 비교의 gold로 판정하지 않음.

## 사례별 고정 검산

| 사례 | 과거 해당 분기 전망, USD bn | 같은 분기 실제 매출, USD bn | 올바른 관계 |
| --- | --- | --- | --- |
| NVIDIA Q2 FY2023 | 8.10 ±2% → [7.938, 8.262] | 6.704, 공시 반올림 6.70 | 기존 전망 범위보다 낮음 |
| Intel Q2 2024 | [12.5, 13.5], 중간값 13.0 | 12.833, 공시 반올림 12.8 | **범위 안이지만 중간값보다 낮음** |
| AMD Q3 2022 | 6.7 ±0.2 → [6.5, 6.9] | 5.565, 공시 반올림 5.6 | 기존 전망 범위보다 낮음 |

Intel의 범위 충족은 매출에만 적용함. EPS나 마진까지 전망을 충족했다는 뜻이 아님. Intel의 현재 공시에는 같은 숫자 범위가 다음 Q3 전망으로도 등장하므로 숫자가 같다는 이유로 Q2 전망을 보존했다고 인정하지 않음. 적절한 반올림은 허용함. NVIDIA FY2023의 해당 분기는 달력 기준 2022년임.

최신 공시에 이미 과거 대비 변화가 설명되어 있으면 No Memory의 정답을 그대로 인정함. AMD 현재 공시는 기대보다 약했다는 사실을 직접 설명하므로 No Memory가 이를 언급해도 환각이 아님. 정확한 과거 전망을 모른다고 밝히는 답변도 사실 오류가 아님.

## 오류가 발생한 단계

1. `source`: 원문을 본 첫 분석부터 오류가 있었는지 확인함. 이미 잘못된 분석이면 Memory 고유의 왜곡이라고 부르지 않음.
2. `store`: 전체 저장소에서 해당 전망을 검사함. **누락 / 모호화 / 거짓 사실화**를 구분함.
3. `retrieved`: 저장소에 정확한 정보가 있었지만 Top-10에서 빠졌는지 확인함.
4. `answer`: 전달된 정보와 현재 공시가 정확한데도 잘못 해석했는지 확인함.

Memory 조건의 오류 하나만으로 인과관계를 확정하지 않음. 후보 사례가 발견되면 같은 현재 입력을 두고 잘못된 Memory의 지위·기간만 복원하는 추가 진단을 별도 실행할 수 있음. 아직 실행하지 않은 복원 결과를 가정해 보고하지 않음.

## 입력 경계와 테스트 범위

- Source Agent의 작업 디렉터리에는 과거 공시 `source.txt`만 배치함. 현재 공시, gold, 후속 질문은 과거 작업에 제공하지 않음.
- Mem0 형성은 과거 요청·전체 공시·실제 분석 메모만 이용함. 미래 질문은 형성 이후 검색에만 사용함.
- 후속 Agent는 동일 현재 공시·동일 질문과 조건별 과거 입력을 받고 Tool 사용을 하지 않음.
- `tests/forecast_memory_test.py`는 원본 SHA-256, 날짜 순서, 전체 gold 인용 구절의 원문 존재, 수치 범위, source/formation 입력 경계를 오프라인으로 검사함.
- 테스트 안의 annotation helper는 **수동 판정 라벨의 의미를 확인하는 예제**이며, 실제 모델 응답을 자동 분류하는 judge가 아님.
- 파일 해시·메서드 경계 테스트만으로 모델의 모든 파일 접근을 보장할 수는 없음. 실제 Source Tool 호출 로그가 허용 파일만 읽었는지도 별도로 확인해야 함.

세 사례는 빠른 존재 확인용이며 모두 반도체 회사임. 실패가 나오지 않으면 null 결과로 보고함. 중간 공시가 생략된 두 검토 시점의 비교이므로, 나중 실적 발표가 미달의 최초 공개라고 주장하지 않음. 이 smoke만으로 금융 전체나 장기 Memory의 일반적인 실패율을 추정하지 않음.
