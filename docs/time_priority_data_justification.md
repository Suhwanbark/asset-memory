# 데이터 정당화 — 현재 업무에서 어떤 정보가 더 중요한가?

## 한 문장

**같은 두 정보가 모두 사실이어도, 현재 날짜와 처리하려는 업무에 따라 우선할 정보가 달라지는지를 평가함.** Memory 형성·검색·압축은 사용하지 않음.

## 무엇을 정답으로 삼았나?

막연한 ‘더 중요한 금융 뉴스’에는 유일한 정답이 없음. 이번 feasibility POC에서는 **명시한 업무를 수행하는 데 직접 필요한, 현재 적용 가능한 근거**로 범위를 좁힘. 정보의 수익률 예측력, 뉴스가 가격에 미친 인과효과, 전문가의 모든 정보가치 판단을 대신하는 지표가 아님.

| 구분 | 정보 A / B | 업무별 정답의 근거 |
| --- | --- | --- |
| 기한이 지난 정보 | 상시 자금 조달 창구 / 더 긴 만기의 한시적 조달 창구 및 종료 공지 | 신규 조달을 원하는 날짜가 종료 전이면 한시 창구, 종료 후면 이용 가능한 상시 창구. 동일한 질문·자료에서 날짜만 바꿈. |
| 오래됐지만 계속 중요한 정보 | 기존 대출의 만기·상환 조건 / 최근의 신규 대출 중단 공지 | 기존 채무의 상환 일정에는 기존 계약 조건이 중요함. 신규 대출 중단이 기존 대출 만기를 자동으로 앞당기지는 않음. |
| 업무에 따라 우선순위 변경 | 과거 주식분할 / 최근 현금배당 | 과거 보유 주식 수를 현재 단위로 환산할 때는 분할, 다음 현금 수입을 계산할 때는 배당이 중요함. |
| 단순 통제 문항 | 합병 추진 / 합병 종료, 또는 금리 결정 / 장기 목표 | 최신 계약 상태·과거 공개 정보·단순 수치 독해. 시간별 정보 중요도의 본실험과 따로 집계함. |

둘 다 필요한 문제에 임의로 순위를 붙이지 않기 위해, ‘전체 투자 매력’이나 ‘총수익률’ 대신 신규 조달 가능성, 만기, 주식 단위 환산, 현금 수입처럼 목적이 분명한 질문을 사용함. 이로 인해 정답은 설명하기 쉬워지지만, 실제 투자자의 복잡한 뉴스 중요도 판단보다 훨씬 좁고 쉬운 과제라는 한계가 있음.

## 실제 자료와 연구자가 만든 부분

- **실제 자료:** Federal Reserve 공식 제도·종료 공지·term sheet, Apple/NVIDIA/Broadcom 공식 공시, 기업·규제기관의 합병 공지, FOMC 성명.
- **연구자가 만든 부분:** 두 자료를 묶는 방식, 짧은 영어 evidence card, 질문, 가상의 보유·차입 상황, 관측 날짜. 실제 고객 질문이나 실제 투자 실행 로그를 수집한 것은 아님.
- **명시적 가정:** 후속 연장·계약 변경 없음, 대상 자산의 적격성 충족, 중도 상환·거래 없음 등. 이는 두 카드로 답할 수 있게 한 시나리오 조건이며, 전체 역사적 시장 상황을 완벽하게 재현했다는 뜻이 아님.
- **정답 작성:** 모델을 실행하기 전에 문항별 정답과 근거를 고정함. 외부 전문가의 독립 정답 검증·평가자 일치율은 아직 없음. 따라서 source-grounded researcher label이지 검증된 전문가 consensus가 아님.

## 규모: 문항 수와 독립 사례 수를 구분

- 총 50문항, 출처 기준 16개 cluster. 각 문항을 A/B와 B/A 두 순서로 실행함.
- 본실험 38문항: 대출 제도 5개와 기업 주식분할/배당 3개, 총 **8개 cluster**.
- 통제 12문항: 합병 4개와 FOMC 성명 4개, 총 8개 cluster.
- **날짜만 바꿔 정답이 바뀌어야 하는 비교는 3쌍**임. 날짜가 바뀌어도 과거 정보의 중요도가 유지되어야 하는 비교는 8쌍임.
- 나머지는 업무가 달라지는 비교나 단일 통제 문항임. 50문항 또는 100회 응답을 50/100개의 독립 금융 사건이라고 보고하지 않음.
- source 수집은 목적 표집임. 금융 뉴스의 모집단에서 무작위 추출하거나 실제 발생빈도를 추정한 것이 아님.

## 누출·출처 QC

1. 원문, URL, 공지 날짜, 원문 hash, 카드에 대응하는 정확한 인용 구간을 저장함.
2. 모든 카드의 출처 공개일이 평가 날짜 이하여야 함. 복수 문서로 만든 카드는 가장 늦은 출처 날짜를 표시함.
3. 현재 내려받은 웹 문서는 당시 원문 snapshot과 완전히 같다고 보장하지 못함. 동적 추천 모듈을 피하고 해당 공식 발표의 본문만 선택함. PDF metadata도 보존함.
4. CPFF/MMLF term sheet는 2020-11-30 문서이며 파일 수정 metadata는 2020-12-22임. 사용한 평가 시점은 모두 그 이후임. 다운로드 날짜를 과거 공지 날짜로 속이지 않음.
5. evidence card에는 근거 내용만 주고, 정답·판정 근거·stratum·source ID는 모델에 주지 않음.
6. 질문·두 카드를 그대로 두고 A/B 순서만 뒤집어 위치 편향을 측정함.
7. 단순 최신 선택·최고령 선택·단어 유사도·무작위 선택을 별도 기준선으로 비교함. 같은 날짜의 recency tie는 0.5 기대 정답으로 처리함.
8. 데이터와 정답의 hash를 추론 전 고정함. 이후 출력 형식 진단(v2)에서도 같은 hash를 유지함. 오답이 나온 사례만 재생성하거나 정답을 바꾸지 않음.

## 직접 확인할 수 있는 출처 예

- [BTFP 최초 조건](https://www.federalreserve.gov/newsevents/pressreleases/monetary20230312a.htm): 최대 1년 만기.

- [할인창구 조건](https://www.federalreserve.gov/newsevents/pressreleases/monetary20200315b.htm): 최대 90일의 초기 대출 기간.
- [Apple 주식분할](https://www.apple.com/newsroom/2020/07/apple-reports-third-quarter-results/), [2024년 배당](https://www.apple.com/newsroom/2024/10/apple-reports-fourth-quarter-results/): 오래된 사실과 새로운 사실이 서로 다른 현재 업무에 필요한 예.

## 어디까지 주장할 수 있나?

이 설계는 **시간·업무를 조건으로 정보의 적용 가능성과 우선순위를 고르는 작은 평가를 만들 수 있는가**를 확인하는 하한선 POC임. 결과가 나쁘더라도 일반 독해·선택지 위치 편향을 먼저 배제해야 함. 통과하더라도 경제적 정보가치를 이해했다고 결론 내릴 수 없음.

다음 확장에 필요한 것은 실패하는 문항을 더 만드는 것이 아니라, 충분한 독립 사건과 사람 검증, 날짜만 바뀌는 명확한 비교, 실제 사용자 업무에 가까운 질문임. Polymarket의 최종 YES/NO 결과만으로 과거 뉴스 A/B의 상대 중요도를 정답 처리하는 방식은 이번에 사용하지 않음.
