# Temporal Evidence POC — 독립 설계 감사

작성일: 2026-09-28. 범위: Prediction-market 사건을 이용한 **현재 시점의 근거 유효성** POC. 이 문서는 설계 검토이며 실험 결과가 아님. 정보 추가/제거 ablation은 제안하거나 실행하지 않음.

## 1. 측정할 것과 측정하지 않을 것

핵심 질문은 **과거에 기록한 주장·전망을 현재 시점의 판단 근거로 그대로 사용해도 되는지, 공개된 후속 기록에 맞춰 구분하는가?**임.

- 측정 가능: 시점·대상·기간이 일치하는 후속 공식 기록을 반영한 현재 적용 가능성 판단.
- 이 POC만으로 측정하지 못함: 정보의 인과적 가치, 예측 정확도에 대한 개별 정보의 기여, 투자 수익, 최적 Memory 구조.
- 사건의 최종 결과와 시장 가격 변화는 개별 정보의 가치에 대한 자동 정답이 아님.
- 사건 종료나 정보의 오래됨만으로 그 정보를 불필요하다고 판정하지 않음. 확정된 과거 사실이 현재 질문에 중요한 근거일 수 있음.

## 2. Gold의 단위와 의미

각 문항은 `event_id`, `as_of`, `old_claim`, `claim_scope`, `public_evidence_before_as_of`, `gold_label`, `gold_citations`를 분리해 보존함. `claim_scope`에는 대상·변수·관련 기간·진술 종류(관측/계획/전망/확정 결과)가 포함되어야 함.

**과거 발언이 실제로 있었는가**와 **지금도 그대로 적용할 수 있는가**는 다른 질문임. 예를 들어 “5월 발표에서 다음 분기 매출을 8.1로 전망했다”는 기록은 이후 전망이나 실제 결과가 달라져도 역사적 기록으로 참임. 평가 질문은 해당 기록을 거짓이라고 분류하게 해서는 안 되며, “현재 유효한 전망도 8.1이라고 말할 수 있는가?”처럼 범위를 명확히 해야 함.

권장 세 범주:

| Gold label | 판정 기준 | 피해야 할 대체 기준 |
| --- | --- | --- |
| `supported_as_of` | cutoff 이전의 인용 가능한 공식 근거가 **동일한 대상·변수·기간**에 대해 현재 적용을 지지함 | 후속 소식이 없다는 이유만으로 확인된 것으로 간주 |
| `superseded_as_of` | cutoff 이전의 공식 수정·철회·확정 등으로 현재 그대로 적용할 수 없음 | 실제 결과가 전망과 다르다는 이유만으로 과거 전망의 존재까지 거짓 처리 |
| `unresolved_as_of` | 제공된 cutoff 이전 기록만으로 현재 적용 여부를 확정할 수 없음 | 미래 최종 결과를 가져와 현재의 불확실성을 해소 |

용어를 `confirm/supersede/unresolved`로 구현하더라도 위 의미를 유지해야 함. 단순히 이후 기록이 더 최신이라는 이유로 우선하는 것이 아니라 같은 범위를 갱신하는지 확인함.

## 3. Circular GT 및 미래 정보 유출 방지

1. 공식 기록의 **공개 시각**이 cutoff 이하인 자료만 Agent와 Gold 판정에 이용함. 사건 발생 시각과 공개 시각을 구분하며, 날짜만 확인되는 자료는 날짜 내 시점 문제에 사용하지 않음.
2. 나중에 갱신된 웹페이지는 당시 버전이 확보되지 않으면 역사적 입력으로 인정하지 않음. 시장 종료 후의 설명·해설도 과거 시점 입력에 섞지 않음.
3. 최종 YES/NO 결과가 기록된 market metadata, resolution 설명, slug·파일명·case ID의 label 표현을 모델 입력에서 제거함.
4. Gold는 원본 출처의 인용 구간과 독립 검토로 확정함. 실험 모델의 답을 Gold로 삼거나 baseline이 틀리는 쪽으로 Gold를 조정하지 않음.
5. 같은 공식 자료를 입력과 Gold 근거로 사용하는 것은 근거 기반 이해 과제에서 가능함. 그러나 그렇게 측정한 점수를 실제 예측 능력 또는 정보의 인과적 효용으로 부르지 않음.
6. 공개된 사건에 대한 모델의 사전 지식 가능성을 인정함. 답변이 허용된 출처로 뒷받침되는지를 별도로 검사하고, cutoff 이후 결과를 인용하면 오염으로 기록함.

## 4. Memory 비교의 경계

기본 비교는 **같은 cutoff까지 완료된 기록**을 각 방식에 전달하고, 이후 동일한 현재 시점과 검토 질문으로 평가하는 구조가 가장 해석하기 쉬움.

- Full dated history: cutoff 이전 허용 기록 전체.
- Concise memory: 위 기록으로 만든 압축본. 직접 작성한 요약 구현이라면 `Concise summary`라고 표기하며 공식 Mem0 등으로 부르지 않음.
- Naive retrieval: 같은 허용 기록으로 구축한 저장소에서 질문을 검색해 전달.
- query에는 현재 시점·대상·검토할 주장 등 업무 정보만 들어가며 Gold, 미래 결과, 정답 후보 설명이 들어가지 않음.
- 각 방식이 실제로 저장한 내용과 최종 Agent에 전달한 내용을 따로 남김. Top-k뿐 아니라 전달 토큰 수도 집계함.
- 현재 입력에 결정적인 후속 공식 기록을 통째로 별도 제공하는 경우, Agent는 과거 Memory 없이도 해결할 수 있음. 이 조건을 사용한다면 **Memory의 필요성**이 아니라 **과거 기억과 현재 근거의 충돌 처리**를 보는 별도 과제로 명시함.
- 현재 방향은 원본 Agent의 Decision 재현 과제가 아님. 원본 Source Agent의 의견을 Gold로 사용하지 않음.

## 5. 최신성·관련성 shortcut 감사

출처 수집 후 다음 단순 규칙의 성능을 모델 결과와 별도로 산출해야 함.

- 가장 최근 문서/주장을 선택.
- 가장 최근 공식 문서가 이전 정보를 항상 덮어쓴다고 가정.
- 질문과 단어가 가장 많이 겹치는 문서를 선택.
- 항상 다수 label을 선택.

모든 사례에서 최신 기록을 고르면 해결된다면 시간에 따른 유효성 과제일 수는 있지만, **최신성을 넘어선 정보 가치 판단**을 입증한 것이 아님. 자연 자료 안에서 후속 무관 기사·재보도, 오래됐지만 유지되는 확정 조건, 실제 수정/철회가 있는 사례를 확보할 수 있는지 확인함. 단, 실패를 유도하려고 임의 문장을 만들어 넣거나 baseline 결과를 본 뒤 사례를 선별하지 않음.

## 6. 30개 사건 규모와 품질 관리

- 목표는 **고유 사건 30개**이며, 같은 사건의 날짜 2개는 독립 사건 2개가 아님. 사건 수와 문항 수를 별도 표기함.
- 포함/제외 기준은 출력 확인 전에 고정함. 필요한 공개 시점·주장 범위·공식 갱신 자료가 없는 사례는 사유를 남기고 제외함.
- 사건·기관·동일 업데이트의 재사용을 식별해 유사 문항 중복을 보고함. 추후 개발/평가 분리는 사건 단위로 수행함.
- 세 label의 실제 구성비를 공개함. 균형을 맞추기 위해 모호한 사례에 억지 label을 붙이지 않음.
- 논쟁적 Gold는 모델 결과를 보지 않은 채 재검토하거나 `ambiguous/excluded`로 분리함. 미해결 Gold를 오답으로 세지 않음.
- 데이터·Gold manifest와 입력을 실행 전에 고정하고 해시를 남김. 수정이 필요하면 별도 버전으로 모든 조건을 동일하게 재실행함.

## 7. 최소 지표와 결과 보고

주 지표는 label 정확도 및 macro-F1, 보조 지표는 세 범주의 혼동행렬임. 특히 `superseded_as_of`를 `supported_as_of`로 판단한 비율을 **무효화된 근거의 현재 재사용 오류**로 분리함.

함께 보고할 항목:

- 허용된 출처로 답변 근거가 뒷받침되는지.
- cutoff 이후 정보를 답변에 사용했는지.
- 근거 없는 확정과 적절한 `unresolved` 응답을 구분했는지.
- 저장/전달 토큰, 검색 수, 실패한 호출, 실제 완료 분모.
- 사건 단위 불확실성. 30개 사건 POC의 결과를 일반적인 금융 Memory 실패율로 확대하지 않음.

오류 분석은 `formation`, `retrieval`, `utilization`의 **관찰 가능한 누락 위치**로만 기술함. 관계가 전달되지 않았다는 관찰만으로 오답의 유일한 인과적 원인이라고 단정하지 않음.

## 8. 실행 전 핵심 체크리스트

- [ ] 질문이 과거 사실의 진실 여부와 현재 적용 가능성을 혼동하지 않음.
- [ ] 모든 Gold 근거가 cutoff 이전 공개된 허용 자료임.
- [ ] 공식 기록의 대상·변수·기간이 old claim과 일치함.
- [ ] `unresolved`가 미래 결과로 억지 해결되지 않음.
- [ ] market resolution 및 label metadata가 입력에 노출되지 않음.
- [ ] Memory 조건마다 동일한 원천 기록과 동일한 질문을 사용함.
- [ ] 단순 최신성/다수 label 규칙으로 과제가 해결되는지 보고함.
- [ ] baseline 성능을 기준으로 데이터 포함 여부를 바꾸지 않음.
- [ ] information utility 전체를 검증했다고 과장하지 않음.

현 단계 감사 결론: 이 설정은 **시간을 고려한 근거의 현재 유효성**을 점검하는 작은 POC로는 타당할 수 있음. 다만 Prediction market의 최종 결과만으로 정보 가치의 정답을 정하는 구조, 또는 모든 문항이 최신 기록을 고르는 것으로 풀리는 구조라면 회의에서 제안한 핵심 능력을 검증했다고 보기 어려움.

## 9. 실제 v1 protocol 교차 검토

검토 대상: `docs/temporal_evidence_poc_protocol.md` 최초 42줄 버전. 주 protocol은 Gold를 `supported / contradicted / insufficient`로 명명함. 위 권장 label과 의미를 대응하되 `contradicted`는 **현재 적용을 직접 반박하는 허용 근거가 있을 때**만 사용해야 함. 자료 부족을 반박으로 처리하지 않음.

큰 설계는 cutoff·동일 원천·null 보고·인과적 효용과의 구분을 충족함. 구현 전 확인 사항:

1. protocol의 “각 premise를 CURRENT statement로 분류”라는 지시와 historical probe가 충돌할 수 있음. 각 probe에 `scope=current/historical`을 두고 “명시된 scope 기준으로 판정”하도록 해야 함. 역사적 사실은 현재 갱신된 상태와 양립 가능함.
2. Fed의 공식 정책 상태 자료를 실제 prediction-market 문항과 혼합할 경우 출처 유형을 분리해 보고해야 함. 공식 이벤트 30개를 실제 거래 시장 30개로 표현하지 않음.
3. API 지역/법적 접근 제한은 우회하지 않음. 공개 연구 데이터 또는 공식 이벤트 기록으로 대체하는 경우 데이터 출처 변경과 측정 범위 변경을 함께 고지함.
4. 단순 공식 상태 판별에서 near-perfect 결과가 나오면 그 작은 능력에는 문제가 관찰되지 않았다고 결론 냄. 이 결과를 실패를 유발할 더 꼬인 데이터 설계의 정당화로 사용하지 않음.

코드 감사는 `method/temporal_evidence_eval.py`가 생성된 이후 별도로 진행할 예정임.

## 10. v1 코드·FOMC 데이터·초기 응답 독립 감사

검토한 구현: `method/temporal_evidence_sources.py`, `method/temporal_evidence_eval.py`. 공식 FOMC 2023–2025년 24개 결정 × 4개 probe를 검토함. 테스트 파일은 `tests/temporal_evidence_test.py`임. 오프라인 초기 20개 테스트가 모두 통과했으며(3.656초), 실제 모델이나 네트워크 호출은 없었음. 테스트 중 출력되는 `DONE`은 mock 응답을 사용한 임시 디렉터리 경로 검증이지 추가 실험 결과가 아님.

확인 범위:

- 고유 사건·Gold/probe 일대일 대응, 연도별 8개 회의, 실제 시장 계약으로의 오표기 방지.
- 공식 HTML/text 해시, 페이지 공개/갱신 날짜와 calendar의 회의록 공개일 일치, cutoff 이후 자료 배제.
- 현재 회의록 공개가 다음 회의보다 앞선다는 점, 다음 회의의 실제 결과가 입력에 포함되지 않는 점.
- 분수·소수·Unicode 하이픈 금리 표기 parser, 생산 코드와 별도의 결정문 금리 추출을 통한 수치 대조.
- 현재 금리와 이전 금리의 동등성에 따른 Gold, 날짜가 명시된 과거 금리 기록의 지속적 참, 공식 2% 장기 목표의 명시적 재확인.
- 미래 금리 단정의 `insufficient` 범위, Gold/case metadata가 요약 형성 prompt에 들어가지 않는 경계.
- 날짜와 source를 포함하는 RAG chunk, 변경된 prompt/model cache 거부, 중복/누락/잘못된 응답 label 검증.

### 결과 해석상 중요한 한계

24개 사건에서 historical record는 항상 `supported`, 2% 목표도 항상 `supported`, 정확한 미래 회의 결과는 항상 `insufficient`임. 즉 **96개 probe 중 72개(75%)는 범주별 고정 label**임. 전체 정확도는 보조로 두고 `policy_state`의 변경/유지 사례를 별도로 보고해야 함. 이는 코드 결함이 아니라 현재 POC의 쉽고 좁은 설계 특성임.

최종 독자에게는 “제공된 근거만 사용하라”고 지시하지만 Gold는 전체 원천 기록으로 정의됨. 압축/검색 이후 충분한 근거가 전달되지 않으면 독자가 `insufficient`로 답하는 것은 정직한 보류일 수 있음. 이 경우 end-to-end 정보 손실은 있을 수 있으나 이를 독자의 잘못된 기억 재사용이나 hallucination으로 부르면 안 됨.

| `fomc_20240918` | 현재 금리 인하와 과거 금리의 차이를 올바르게 판정함. 요약의 2% 관련 표현은 진전·복귀·예측 중심이고 장기 정책 목표가 명시적으로 정리되지 않아 `insufficient`로 보류함. 문자 그대로 제공된 근거만 요구하는 기준에서는 합리적인 보류로 볼 수 있으며, 오래된 금리 재사용 오류가 아님. |
| `fomc_20250129` | 요약에 2025-01-29 현재 금리 4.25–4.50%가 분명히 있음. 독자는 질문의 2025-02-19까지 상태 지속이 직접 입증되지 않는다는 이유로 `insufficient`라고 함. 따라서 수치 저장 손실로 분류하면 안 됨. 요약에서 회의록 공개일/커버리지 경계가 약화되고, 원 지시문의 closed-world/current-state 의미가 엄밀히 고정되지 않은 복합적 해석 문제임. |

v2에서 “현재 상태 = cutoff까지 제공된 기록이 확립하는 최신 적용 가능한 상태”라고 명시하는 수정은 이 애매함을 줄이는 방향임. v1 응답을 보존하고 데이터·Gold·질문·요약은 고정한 채 모든 조건에 같은 지시문 수정을 적용해야 함. 수정으로 점수가 좋아져도 새로운 효용 판단 능력을 입증한 것으로 해석하지 않음.

## 11. v1 추가 표본 및 v2 최종 오류 검토

v2의 current-scope 지시문과 v1 요약 cache 재사용 경계를 검사하는 테스트 2개를 추가함. **22개 테스트 모두 통과(3.918초)**. 테스트는 모델·네트워크를 호출하지 않음. 구현의 Naive RAG는 **단어 TF-IDF cosine**이며 dense embedding 검색이 아님.

### v1의 추가 검토

v1의 오류 20개 이유 문장을 확인함. 모두 `insufficient`이며, 이유 문장상 현재 날짜까지의 지속을 확인하지 못했다는 보류 13개와 2% 장기 목표의 명시적 근거가 부족하다는 보류 7개로 나뉨. 이는 이유 문장의 분류이며 저장 내용에 관한 자동 인과 판정이 아님. 다음은 원래 요약 전문까지 추가 대조한 대표 사례임.

- `fomc_20230614`: 금리 5.00–5.25%와 “objectives remained ... 2% longer-run inflation”이 모두 요약에 있음. 두 `insufficient`는 저장된 수치/목표의 누락이 아니라 6월 기록을 7월 cutoff까지 적용하는 의미에 관한 보류임.
- `fomc_20240612`: 최신 금리 5¼–5½%는 요약에 정확히 존재함. 반면 2%는 물가 진전·수렴 전망으로 쓰였고 장기 정책 목표가 명시되지 않음. 같은 사건 안에서도 금리 보류와 목표 보류의 원인이 같다고 처리해서는 안 됨.
- `fomc_20250917`: 4–4¼%로의 인하는 명확히 보존됨. 2%는 2027년 물가 복귀 전망으로만 남아, 목표라는 역할 정보가 약화됨.
- `fomc_20251029`: 새 금리 3¾–4%와 2% goal이 요약에 있지만, 11월 cutoff까지 현재 상태가 유지됨을 확인하지 못한다는 보류임. 과거의 더 높은 금리를 현재라고 선택한 것이 아님.

정답 표본으로 `fomc_20230322`, `fomc_20241218`, `corporate_adobe_figma`의 현재 상태 probe도 전문 대조함. 각각 최근 금리 인상, 금리 인하, 인수합병 취소가 요약에 남아 있었고 최종 독자는 오래된 현재 상태 전제를 거부함. Adobe–Figma 사례에서는 과거 CMA의 provisional 판단과 이후 계약 종료를 함께 보존하여 과거 사실까지 거짓으로 뒤집지 않음.

### v2의 90개 최종 응답 검토

검토 시점 `result/temporal_evidence_poc_v2/report.json`에는 30개 사건 × 3조건의 90개 응답이 존재했음. 오류 7개는 모두 concise-summary 조건임. FOMC 현재 금리 판단은 24/24이며 오래된 현재 금리 전제를 수용한 오류는 관찰되지 않음.

1. **장기 목표 근거 부족으로 인한 보류 6개**: `20240131`, `20240612`, `20240918`, `20241107`, `20250917`, `20251210`의 FOMC 사례. 각 요약 전문과 답변을 대조함. 요약은 2%를 향한 진전·물가 복귀 전망·금리 인하를 위한 조건을 남겼으나 “2% longer-run objective”라는 역할을 직접 명시하지 않음. 전체 원문 기준으로는 정보 보존에 실패한 오답이지만, 제한된 제공 근거만 판단하는 독자에게는 합리적인 보류로 볼 수 있음. 오래된 잘못된 상태를 확신하여 재사용한 사례가 아님.
2. **label–reason 불일치 1개**: `fomc_20230201`, probe `p2`. 요약에는 2022-12-14 금리 4¼–4½%가 정확히 있음. 최종 label은 `contradicted`지만 이유는 같은 수치를 확인한 후 “Actually this matches the claim.”이라고 끝남. 구조적으로 유효한 JSON이지만 응답 내부가 불일치함. 정해진 label 채점에서는 오답을 유지하고, 원인 분석에서는 저장 손실·시간 혼동이 아닌 **최종 응답 일관성 오류**로 분리해야 함. 선택적 재시도나 이유를 근거로 label을 사후 교정하지 않음.

v2는 v1에서 점수 차이를 만든 범위 애매함을 줄였고, 원래의 가설적 실패인 **낡은 근거를 최신 근거보다 우선해서 적용하는 현상**은 이 간단한 공식 상태 판별 POC에서 확인되지 않았음. 2% 목표 생략은 일반 요약의 정보 선택 문제를 보여주지만 정보의 시간적 효용을 잘못 판단했다는 단독 증거가 아님.

자동 채점은 label 비교임. 현재 JSON validator는 인용 ID의 실재 여부나 label–reason의 의미적 일관성을 자동 검사하지 않으므로, label 정확도를 인용 정확도 또는 전체 답변 충실도와 동일시하지 않음.
